# Аккаунты и социальный вход

## Вход по email

Откройте приложение и нажмите **«Зарегистрироваться»**. Укажите имя, email и пароль из 12–128 символов. Email используется как логин, отправка подтверждающих писем пока не подключена. Пароль можно изменить через аватар в правом верхнем углу. При смене пароля остальные сессии завершаются.

При регистрации заполните поле **«Повторите пароль»**. Совпадение проверяется в браузере и на сервере.

Если до обновления уже были совещания без владельца, они автоматически перейдут в **первый зарегистрированный аккаунт**. Код владельца не требуется. Последующие аккаунты начинают с пустого пространства. Зарегистрируйте свой первый аккаунт на локальном устройстве до предоставления доступа другим людям. База не удаляется и не переименовывается; имя `alem.sqlite3` сохранено для совместимости.

Сессия действует до 12 часов; после 2 часов без запросов она истекает. Периодическое обновление открытого приложения считается активностью. Выход немедленно отзывает текущую сессию на сервере.

## Подключение Google

1. Создайте OAuth-приложение типа **Web application** в Google Cloud / Google Auth Platform. Настройте экран согласия и тестовых пользователей, если приложение ещё находится в режиме тестирования.
2. В разрешённых redirect URI укажите точно `http://127.0.0.1:8765/api/auth/oauth/google/callback` (или callback на вашем HTTPS-домене).
3. Скопируйте `.env.example` в `.env` и заполните `DAUYS_GOOGLE_CLIENT_ID` и `DAUYS_GOOGLE_CLIENT_SECRET`.
4. Перезапустите приложение и используйте адрес из `DAUYS_PUBLIC_URL`. При использовании `localhost` вместо `127.0.0.1` измените и этот параметр, и URI в панели провайдера.

Запрашиваются только `openid email profile`. Используются authorization code, PKCE S256, одноразовый state, привязанный к браузеру, и серверный запрос UserInfo. Приложение идентифицирует пользователя по Google `sub`, а не по введённому email. [Документация Google](https://developers.google.com/identity/openid-connect/openid-connect).

## Подключение Facebook

1. Создайте приложение Meta с продуктом Facebook Login для веб-сайта и разрешениями `public_profile`, `email`.
2. Добавьте точный адрес `…/api/auth/oauth/facebook/callback` в Valid OAuth Redirect URIs и укажите допустимый домен приложения. Требования к HTTPS/localhost и режиму приложения зависят от настроек Meta; сверяйте их с панелью приложения.
3. Заполните `DAUYS_FACEBOOK_CLIENT_ID`, `DAUYS_FACEBOOK_CLIENT_SECRET`, `DAUYS_FACEBOOK_API_VERSION` в `.env` и перезапустите сервер.
4. В режиме разработки вход обычно ограничен участниками/тестерами приложения; доступ остальных пользователей требует корректного режима и разрешений Meta.

Используются обмен кода на сервере, одноразовый state с cookie браузера и `appsecret_proof` при чтении профиля. Идентификатор — Facebook `id`; отсутствие email не мешает входу. [Документация Meta](https://developers.facebook.com/docs/facebook-login/guides/advanced/manual-flow/).

**Без ключей кнопки остаются неактивными.** Интеграции проверены с подменой ответов провайдеров; настоящий вход необходимо проверить после настройки ваших OAuth-приложений. Аккаунты email/Google/Facebook не объединяются автоматически даже при совпадении email: это предотвращает захват аккаунта через неподтверждённую почту. Пока каждый способ входа создаёт отдельное пространство.

## Защита и границы

- Пароли: scrypt N=131072, r=8, p=1, случайная соль 16 байт. [Основание выбора параметров — OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
- Случайный идентификатор сессии находится в HttpOnly/SameSite=Lax cookie. В SQLite хранится SHA-256 идентификатора. Для HTTPS включается Secure.
- Для изменения данных требуется CSRF-токен сессии; проверяется Origin и запрещаются cross-site запросы (исключение — строго ограниченные OAuth callbacks).
- Совещания, аудио, экспорт, поиск, редактирование и напоминания проверяют владельца. Кэш распознавания также разделён по владельцам.
- Число попыток входа ограничено по аккаунту и IP. Ограничения сохраняются в SQLite и не сбрасываются обычным перезапуском.
- CSP, запрет встраивания во фреймы, no-store и экранирование данных в интерфейсе.
- OAuth связывается с внешним сервисом только при выборе социального входа; записи и протоколы ему не отправляются. Обработка речи остаётся локальной.

Это локальное приложение с аккаунтами, а не готовая корпоративная платформа: нет MFA, подтверждения email/SMTP-восстановления, SSO организации и шифрования SQLite/аудио. Доступ к файлам компьютера позволяет обойти защиту аккаунта приложения. Сервер по умолчанию остаётся на loopback; изменение `DAUYS_PUBLIC_URL` не публикует порт. Для размещения в сети отдельно нужны TLS, безопасная настройка reverse proxy/доверенных Host, резервные копии и политика хранения.

Если локальный пароль потерян, владелец машины может выполнить `python scripts/reset_password.py email@example.com` из окружения проекта. Пароль вводится скрыто в терминале; все сессии этого аккаунта отзываются. Скрипт не восстанавливает аккаунты Google/Facebook.
